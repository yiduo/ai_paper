## 约束差别为什么会改变下一步

当前候选用 F025 的正尾项分离来保留一个精确标记。尾项足够小会避开已保留的倒数，却可能引入更大的分母。因此，它不能直接满足“指定第二大分母”这个真实调用；也没有提供有限允许分母集、最短输出或最大分母保证。不能将实际调用降成较弱需求后声称已经适用。

原论文 Theorem3.2 与早停接口说明有限允许多重集搜索的输出。对应软件实际包含这类接口及上述调用；这些都是旧方法。后续若研究有约束的请求，必须以它们及已读过的旧精确标记构造为比较对象。现有旧方法可能已足够；本轮没有性能数据来判断增量。

选读范围为原论文第 1–2、6–7 页的定义／声明、第 13–18 页选定控制与实现接口、第 19–20 页作者成本报告、第 21–22 页实际调用。第 7、22 页公式及约束已实际查看像素。并未审核整篇证明；作者的运行时间与 6000 个标记范围没有在此复现。

## 运行环境与证据限制

固定 Dense-Egyptian-Fractions 提交为 `30a3915c898e45f61b225b79c3efc1c9f765d2c5`。完整读取 README、Python wrapper、主 Scheme、猜想调用和 MIT 许可；依赖的数学、分支、素数和多线程模块未取得或审核。Python wrapper 实际调用 `chez` 并加载编译后的 `ufrac.so`，不是独立的 Python 求解器。当前 PATH 未发现相关 Scheme 命令；实际检查的 Python3.12.14、3.14.8 均无 SymPy。未安装、执行、编译或修补这些旧工具。

Eppstein 程序的默认 `greedy` 会遍历分母分支，不等于 SymPy 的单路径贪心。选读的 subroutine 中仍有 `keywords.iteritems()`；本轮没有执行该接口或确认完整兼容性。不能把静态观察当成已复现缺陷。

原始 issue 元数据的评论数为 10，本次评论 API 返回 20 个对象；全部返回正文已读，但这个计数差异未解释。两份原始响应散列保留，不宣称读完全部历史。正文 PDF 的 Web 读取超时、Python 内容类型不支持、README 的一次 TLS EOF 均有记录；后续用正常 TLS 的定量获取或官方内容 API取得同一来源，没有绕过 TLS。
