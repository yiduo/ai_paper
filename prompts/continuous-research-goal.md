本阶段不以证明新定理、补全数学理论或扩大知识边界为目标。发现新数学问题时记录下来，回到应用挖掘主线。工程试点、真实业务接入和行业合作遵循纲领中的人工闸门；不要自行对外承诺效果。

保持探索与深入验证两条路线：

- 对证据较充分的线索做深入检验和转化准备。
- 持续为未覆盖成果族、远距离类比、大胆猜想、反向工程需求和跨族组合保留实际探索资源。

资源分配可以根据证据调整，但必须记录理由，不能让熟悉领域或早期成功案例垄断投入。可以降低某条线索的优先级，不因领域遥远、暂时难测或没有先例删除它。

全局最优不能靠自我宣称来保证。用广泛覆盖、备选路线比较、可证伪实验、机会成本和周期复盘降低陷入局部最优的风险。

### 四 持续迭代循环

在可用工具、权限和预算内重复以下循环：

1. **恢复状态**：读取总目标、路线图、最新状态、上次全局复盘和相关失败记录；确认现在最大的瓶颈。
2. **选择工作包**：定义目标、输入、可证伪假设或工程验收条件、预期产物、资源上限，以及停止或转向条件。
3. **执行并取证**：实际读原文、查引用、写代码、运行实验、检查输出；保存输入版本、配置、命令、日志、结果和限制。
4. **局部检查**：确认数据、实现和推断是否支持本轮结论；检验失败时区分实现错误、数据问题、前提不成立和假设不被支持。
5. **更新共享记录**：将证据、卡片、状态和新问题写回唯一的规范数据源，刷新进度和下一步。
6. **判断是否触发全局回归**：达到触发条件时先完成回归，再重新选择工作。
7. **继续推进**：有可执行的后续工作就继续，不因完成一个样例、修好一个模块或写完一份报告而结束总任务。

“实质工作包”指产生可审查研究或工程结果的一组工作，不是一次工具调用、一个文件修改或一段文字。

默认每完成 **3 个实质工作包** 做一次全局回归；每完成一个主要里程碑、出现关键反证、发现上游撤回或重大数据问题时，立即回归。连续两个工作包没有新增有效证据或信息增益时，也提前回归。

这一节奏是执行默认值，不是纲领中的科研结论。将其放入配置；调整必须记录原因，不得用调整频率逃避复盘。

### 五 全局回归必须回答的问题

将每次回归写入 `reports/retrospectives/`，至少回答：

1. **目标对齐**：本轮新增了什么可追溯、可检验的应用价值？是否偏向堆摘要、造平台、重复调参或证明新定理？
2. **覆盖与偏差**：哪些成果族、学科、方法和应用领域仍是空白？是否只挑容易验证的方向？远类比和大胆猜想是否仍有实际探索？
3. **证据变化**：哪些假设被支持、削弱或推翻？有哪些反例、失效前提、规格不一致或撤回依赖？哪些结论需要降级？
4. **路线比较**：至少比较当前路线和一条实质不同的可行路线；同时考虑“旧方法已足够”或“这个新结果没有应用增益”的零假设。
5. **机会成本**：如果现在重新开始，仍会把下一份资源投给当前方向吗？若会，依据是什么；若不会，转向哪里？
6. **技术与数据回归**：数据模式、引用、依赖传播、卡片导出、失败记录、代表性实验和核心测试是否仍正确？不能只检查本轮新增部分。
7. **明确决策**：列出继续、扩大、缩小、暂停、转向和等待外部输入的工作，以及对应证据；更新下一批优先级和资源分配。

回归必须能够改变计划。不能只写“方向正确，继续推进”。如果当前方向优于备选，也要给出支持这一判断的可核对依据。

局部实验结果好，不自动意味着全局方向正确；全局方向合理，也不意味着每个局部假设都应保留高优先级。

### 六 六阶段流水线与共享数据

建立规范的数据模型，支持以下连续流程：

1. **解析与拆解**：记录主命题、关键引理、方法、构造、常数与界，并写出前提、适用范围和原文定位。形式化与自然语言命题需要对照，不能由标题或摘要推断全文。
2. **历史谱系**：查明前驱、旧结果的条件与界、已有应用、依赖关系及同类成果族；新增结果是否可替代旧结果，需要逐项比较条件。
3. **方法抽取**：将结论、方法、构造转写为领域无关的“输入—输出—条件”，保留出处和不能迁移的限制。
4. **跨域映射**：同时执行结构匹配、工程需求反向检索、跨领域联想和两到三个成果族的组合。按纲领保留向 10 个不相关领域尝试映射的探索记录，允许结果是未找到合理连接，禁止凑数。
5. **假设与检验**：定义机制、可证伪假设、基线、外部裁判和实验；附怀疑者与辩护者的意见，记录实际结果。
6. **排序与转化**：综合影响、可行性、达到应用所需时间、证据可信度和资源成本排序，提出有依据的试点方案；涉及人工闸门的状态必须等待真实审核。

知识图谱是研究记录的唯一规范来源，卡片、报告和看板由它生成或与它建立严格引用关系。不能让聊天结论成为另一套事实数据库。

明确区分原文主张、已核对事实、模型假设、实验观察和人工决定；“写入图谱”不等于“命题为真”。节点和边需要稳定 ID、出处定位、版本、证据状态、时间和依赖关系。

初期优先使用便于版本控制和迁移的结构化文件及轻量查询方案。只有真实查询、规模或协作需求证明必要时才引入复杂基础设施，并记录架构决策。

应用卡片必须覆盖纲领全部字段，并补充版本、完整依赖链、模型来源、检验规格、运行标识、复现入口、适用边界和重访条件。不能把文案相似的卡片当作独立假设重复计数。

### 七 证据标准与人工闸门

数学可信度、应用检验结果和工作流状态必须分开管理。

数学可信度沿用纲领：

- **A**：已有形式化，且形式化命题与自然语言命题的一致性经真实人工审核。
- **B**：有 Lean 证明，规格尚未经人工审核。
- **C**：只有自然语言证明。
- **D**：已撤回或发现错误，不能直接用作应用结论的依据。

保留上游形式化声明、本地构建或 Comparator 检查、人工规格审核的不同状态。看见 `.lean` 文件不代表本地验证通过；Lean 检查通过也不代表自然语言规格得到人工确认。一个成果族中的部分形式化不自动覆盖全族。

应用卡片的理论可信度取完整依赖链中最低等级；缺失或无法核验的依赖明确标为未知，不推定可信。撤回证明不等于原数学命题已被证伪，其中的方法和构造可以作为新的独立对象重新评估，不能自动恢复原结论。

应用检验结果分为通过、待定、观察、否定；工作流状态另记为候选、检验中、待人工、试点、归档等。不能将“实验支持”自动升级成 A 级，也不能将“模型有信心”当成通过。

严格执行以下规则：

- 引用应能定位到具体版本、命题、页码或段落。DOI 或链接可打开只验证来源存在，还必须核对原文是否支持被引用的内容。
- 关键映射和假设按纲领由至少两家不同模型提供独立结果，保留模型、输入、输出和时间。相同供应商的多个角色不能冒充跨供应商复核；模型交集优先检查，差异和单方线索仍保留。
- 缺少第二家模型、数学审稿人或领域专家时，记录缺口并继续可独立完成的部分；不能伪造其调用、评审、身份或签字。
- 怀疑者和辩护者尽量在未见对方结论前审查同一材料，意见并列保存。单模型角色扮演只能算辅助自查。
- 只有符合纲领的具体否定依据，并获得至少两名真实审稿人的确认，才能进入正式“否定”归档。否则保存检验不利的证据并标注待审核，不删除线索。
- 每周实际运行期间按纲领抽取 5% 的入库线索准备人工复核；未获复核时明确挂起。人工抽检发现的事实错误率超过 10% 时，暂停受影响环节的自动扩张并修复。远距离联想比例与事实错误率分别统计。
- 试点需满足纲领规定的 A 级依赖和人工审查条件。自动化研究无法替代这些责任。
- 敏感方向按纲领分流到受控流程。公开产物仅保留适合公开的状态与必要说明，不把受控材料写入待公开的仓库历史。

纲领中的种子方向用于校准，不能直接计作项目发现。已经看过种子清单的生成过程不能宣称“盲测独立重新发现”；需要该指标时，隔离生成输入，保留运行证据。

### 八 用可复现实验判断应用价值

每项检验先写出可被证伪的预测、适用范围、成功与失败标准，再运行：

- 使用能代表实际问题的公开基准、数据或明确标为合成的实例；说明为何有代表性。
- 比较合理的现有方法、旧数学结果或不使用该零件的基线，区分“有无该零件”和“仅改变实现”的效果。
- 记录正确性、质量、时间、内存、资源成本等相关指标；不能只展示最有利的一项。
- 对随机实验记录种子并做必要的重复；对选择过参数的实验使用独立验证数据或任务，避免在同一数据上调到成功。
- 给出适当的误差、稳定性、消融和边界检查。严格区分数学推导、数值观察和统计外推，不将有限实验说成证明。
- 保存环境与依赖版本、配置、数据校验值、命令、原始输出和自动汇总方法，让结果可被重跑。

检验标准不能在看到结果后悄悄改变。若标准或场景确需调整，生成新版本并保留旧结果与调整理由。比较算法时采用公平的资源与调参条件。

外部检验包括可核对的数值实验、仿真、基准或真实领域专家评审；模型评分、模型互相赞同和“代码运行成功”本身不构成应用有效的证据。

卡片计数采用明确口径：

- **候选连接数**：去重后有具体映射与条件的连接数量。
- **已初检卡片数**：字段完整，已实际执行至少一种外部检验并留有证据的卡片；结果可以支持、观察或不利。仅写好实验计划、缺资源待定的卡片不计入。
- **有效线索数**：得到外部证据支持，且结论未超出该证据适用范围的卡片数量。
- **原型或数值验证数**：不同假设的可复现检验闭环数量，另列正面、负面和不确定结论；不能把同一假设的十次运行算成十条。
- **人工分级数与试点数**：分别依据真实审核记录和试点证据统计。

分别报告入库率、结构化拆解覆盖率和六阶段完成覆盖率；不能把已登记 372 个编号说成已完成全部研究。

具体要求：

1. **可运行**：提供最少步骤的安装和小样本端到端演示，以及扩展到全量的明确命令。实际验证快速开始，不能只写预期命令。
2. **可复现**：锁定依赖和输入版本，提供确定的配置、缓存与断点恢复机制；无外部模型凭证时能跑公开样例与核心测试，并明确样例不是正式研究结果。
3. **可维护**：模块职责清楚，稳定 ID 和数据约束可检查；核心逻辑、引用与依赖失效传播、状态转换、卡片导出及代表性闭环有实质测试。
4. **可审查**：自动生成的事实性条目均有出处和生成记录，重要决策有理由，失败记录可检索；报告标明已验证、待核验及已知限制。
5. **可贡献**：说明如何新增成果族、补充历史文献、提出连接、提交反例、复现实验和完成审核。中文说明清楚，公开入口按需要提供英文概览。
6. **可发布**：明确本项目代码、文档、派生数据和第三方材料的许可与署名。保留上游许可；本地上游目前包含 Apache-2.0 文本，但不能据此推定所有外部文献都有相同许可。
7. **仓库卫生**：不提交密钥、个人信息、私有审稿内容、缓存、虚拟环境和大体积可再生成文件；大数据以清单、校验值及允许的获取方式管理。
8. **上游管理**：不要把嵌套的 `math/.git` 当成本项目历史。默认使用版本清单和获取脚本引用上游；如选子模块，解释原因并验证首次克隆流程。
9. **持续集成**：在干净环境执行适度的格式、类型、关键测试、数据模式与小样本闭环检查；依赖外部服务、昂贵计算或人工的步骤单独标记，不能用 mock 通过证明真实研究通过。
10. **发布状态准确**：区分本地保存、本地提交、推送、公开仓库与正式版本发布。按既有授权和远程配置执行发布；缺少必要信息时先完成本地可审查产物，不能假报已在 GitHub 开源。

### 十 保存状态与接续执行

维护少量清楚的执行入口，优先复用现有等价文件：

- `docs/roadmap.md`：总目标、里程碑、验收条件和依赖。
- `state/status.md`：真实进度、主要证据、当前瓶颈、审核缺口和下一步。
- `state/backlog.json`：可执行任务及优先级、依赖、状态与验收口径。
- `docs/decisions/`：会影响路线、证据或架构的重要决定。
- `reports/retrospectives/`：周期性的全局回归记录。

这些是项目执行状态；研究事实仍由规范数据源管理，避免多份状态相互冲突。

每个工作包结束后保存状态；发生上下文压缩、会话中断、预算耗尽或工具不可用前，尽可能留下接续检查点，包含：已完成内容及证据、未完成原因、正在运行的任务、不能重复的失败路径、恢复命令和下一个具体工作包。

恢复后先核对磁盘和正在运行任务的实际状态，再续做；不能因对话丢失就从零重建或再次执行已有昂贵实验。

对常规、可逆的本地实现与研究选择自主推进。仅在目标变更、确实缺少必要资源、必须由人完成的审核或超出现有授权的行动上请求输入。请求时说明已经完成什么、具体缺什么、影响哪个步骤；同时继续不依赖该输入的工作。

遇到障碍时依次尝试合理修复、替代数据或方法、其他可执行方向。没有有效路径时如实说明阻塞和恢复条件，不无限重试，不用模拟材料填补真实证据。

### 十一 里程碑与最终验收

按以下阶段推进，并在每个里程碑检查整体方向：

| 里程碑 | 完成依据 |
| --- | --- |
| M0 事实盘点与项目启动 | 固定语料版本，解释数量口径，建立全局地图、规范模式、路线图和最小运行入口 |
| M1 代表性闭环 | 不同类型成果族跑通从原文到卡片和外部检验的流程，暴露并修复模式与方法问题 |
| M2 全量知识底座 | 全部基线成果族完成结构化拆解、可信度与历史谱系，方法零件可检索，缺口不被掩盖 |
| M3 广泛连接 | 至少 500 条去重候选连接、至少 150 条真实人工分级记录，并有跨域、远类比及组合探索证据 |
| M4 检验与排序 | 至少 100 张实际初检卡片、至少 10 条可复现原型或数值验证，按证据区分结果并给出资源排序 |
| M5 开源交付 | 干净环境复现通过，文档与代码一致，来源与许可清楚，发布所需资料齐备，阶段报告可追溯到证据 |

最终逐项输出验收矩阵：“要求—实际结果—证据路径或命令—差距—状态”。以下情况均不能宣告总目标完成：

- 只有项目骨架、计划、摘要、模拟输出或少量漂亮样例。
- 数量达到但去重、来源、实际检验或人工记录不满足要求。
- 所需人审、第二家模型复核或外部检验缺失，却声称已经通过。
- 测试通过但研究结论无法溯源，或研究报告存在但新使用者不能复现。
- 通过删除失败、修改统计口径或放宽验收条件掩盖差距。

如果真实资源或证据无法支持全部目标，交付已完成的可审查成果、差距和继续条件，明确整体仍未完成；不得自行把目标改成已经完成的子集。

### 十二 现在开始

先检查项目真实状态，并按顺序执行：

1. 读取纲领及上游入口，完成语料和版本盘点，列明关键差异与未知项。
2. 建立全局目标、指标口径和验收矩阵，选定第一批有代表性的成果族及选择理由。
3. 建立足以支撑真实研究的最小工程基础，并立即运行代表性闭环。
4. 保存证据和进度，执行必要的局部检查，按规定触发全局回归。
5. 根据证据重排优先级，继续下一批工作，逐步扩大覆盖并完成第一阶段目标。

进展汇报简明回答：新增了什么可验证成果、改变了什么判断、还有什么缺口、下一步为什么值得做。涉及完成状态时附可核对的文件、数据或运行结果。

请开始实际执行，并持续遵循“全局判断—选择工作—执行取证—局部检查—定期回归—调整路线—接续推进”的循环。
